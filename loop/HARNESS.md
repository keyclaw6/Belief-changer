# Harness bindings — v2

The reusable factory is driven by one persistent top-level **Pi Coding Agent** through explicit `scripts/factory.py` tasks. Live model execution uses **OpenCode Go only**. `factory/config.json` contains one generator route, `opencode-go`, with no Zen/Vercel/ChatGPT/OpenCodex/OpenCode-CLI fallback. A host such as ChatGPT may inspect durable state and schedule supervision, but it is not a factory model provider and must not impersonate a Pi factory role.

The external profile is intentionally null until an independent model family available through **OpenCode Go** is explicitly configured. Independence is a model-family property, not permission to switch provider. If an independent evaluator is unavailable through OpenCode Go, stop. There is no silent fall-through to the generator or to another service. Research access follows docs/RESEARCH-ACCESS.md. Browser operations must use the dedicated CloakBrowser/NopeCHA profile and Agent-Reach/OpenCLI social backend with a fresh live preflight. Direct permitted HTTP/RSS/PDF retrieval remains available for primary sources; no stock-browser fallback. Access failure is not scarcity.

A command adapter receives {task,prompt} as JSON on stdin, uses a fresh temporary working directory, and returns exactly {output,model,family,route,usage} on stdout. argv is an array, never shell text; environment forwarding is allowlisted. This is process isolation, NOT an operating-system sandbox. Use a trusted adapter and appropriate external sandbox for tools. Do not let an evaluator read repository scores/history or load an ambient author-identity prompt.

An existing agent harness may instead read a frozen task, call the requested isolated role and submit the strict JSON response plus actual execution metadata. Imported metadata is the operator's assertion, not cryptographic provider attestation. Paid execution requires --allow-paid; supplying that flag is an explicit operation, not part of tests or CI.
